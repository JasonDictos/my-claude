Third alpha: consoles, a shortcut table you can actually read, and fixes from running it on
two machines.

**Install**

```bash
# Fedora 44
sudo dnf install https://github.com/JasonDictos/my-claude/releases/download/v0.0.3-alpha/my-claude-0.0.3-0.1.alpha.fc44.x86_64.rpm
# Ubuntu 26.04 / Debian
curl -LO https://github.com/JasonDictos/my-claude/releases/download/v0.0.3-alpha/my-claude_0.0.3-alpha_amd64.deb
sudo apt install ./my-claude_0.0.3-alpha_amd64.deb
```

You also need [Claude Code](https://docs.anthropic.com/claude-code) (`claude`) on PATH.
On any other x86_64 Linux: the source install (`install.sh`, see the README) and, for the
window, `mc-term-0.0.3-alpha-x86_64-linux` below (one static binary; put it on PATH as `mc-term`).

**New**
- Consoles: `Ctrl+Shift+N` opens a plain shell on the machine of the tab in front
  (console1, console2…, unique names; double-click a tab to rename). They share one panel
  that floats over the project, always on top: drag it, size it, minimise it to its title,
  maximise it. Closing it only takes it off that project; pinned, it shows over every one.
  The Console menu shows/hides it (opening a console when there is none), walks the
  consoles, renames and pins. Each machine has a Consoles entry in the list.
- Settings → Shortcuts is a table: action, its key, your own key (click, press the keys,
  Esc clears), on or off. Taking another action's key asks first and turns that action off;
  a key the desktop keeps for itself (KDE's global shortcuts) is refused, since it would
  never reach the window.

**Changed**
- `Ctrl+Shift+N` is New console; Next pane keeps `Ctrl+Shift+Tab` and `Ctrl+Shift+O`.

**Fixed**
- Started from the desktop's menu, the window is found in `~/.local/bin`; without one it
  says where to get it.
- Restart relaunches the peer (it typed into the pane's one-key prompt and closed it).
- A Claude on another conversation in a peer's folder is no longer taken for the peer, nor
  killed by restart, remove or take over.
- A finished turn's mark clears once its terminal has been looked at; a question's stays.
- The window in use takes back pane sizes that another machine's window changed.
- `gui --install` no longer replaces a deployed window with a link to itself; the old
  `gui.remote` setting becomes a connected machine.
- Turning the show/hide key off in Settings releases it in KDE.
